# 公共模板

## 新窗口任务公共入口规则

- 主线程只读取项目提示词文件和 `多代理工作流` 中的公共模板、主线程调度模板、当前需要创建的角色模板；不要读取项目提示词文件指定的项目事实源正文来接管子代理判断。
- 本轮临时需求只来自项目提示词文件指定的临时需求文件，只能由需求架构子代理定位和读取，主线程不能直接读取、归纳或拆解。
- 按阶段闸门依次创建需求架构、程序员、启动和测试子代理；不再创建检验子代理。需求架构、程序员、启动和测试每个阶段默认都只创建或复用本轮唯一同角色子代理，除非该子代理上下文不足、阻塞、失败、需拆分或已失效。
- 即使用户发送的是“全量测试”“只用浏览器测试”“验证”或“测试”入口，也必须先通过需求架构闸门产出本轮计划和本轮测试计划；不得因为看起来只是测试就跳过需求架构、程序员、启动和计划阶段直接创建测试子代理。
- “全量测试”“只用浏览器测试”“验证”或“测试”只限制最终测试范围，不改变主线程调度身份和阶段顺序；入口消息中的“只执行浏览器端验证”不能解释为主线程亲自测试、不能解释为立即创建测试子代理，也不能解释为跳过本轮计划中仍未完成的编码或修复任务。
- 入口为“全量测试”时，最终测试范围为浏览器端和宿主端；入口为“只用浏览器测试”时，最终测试范围只包含浏览器端，不执行宿主端测试项。无论哪种入口，都不能跳过需求架构、程序员和启动闸门。
- 需求架构闸门通过后，如果主线程摘要显示存在需要程序员处理的本轮计划未完成任务，主线程必须先创建或复用本轮唯一程序员子代理，让它按清单顺序连续完成这些任务；程序员阶段未完成前禁止创建启动子代理或测试子代理。
- 本轮所有子代理阶段都必须串行执行；同一时刻只允许一个本轮子代理处于运行中，不允许并行创建多个需求架构、程序员、启动或测试子代理，也不允许按单个需求标题、单个计划项、单个启动检查项或单个测试项逐项新建同角色子代理。
- 测试阶段不能并行；同一轮只创建一个测试子代理，该测试子代理必须按本轮测试计划串行验证浏览器端、宿主端或当前场景指定范围，并持续更新测试状态。
- 具体测试范围以本轮测试计划和当前任务场景说明为准。

## 共同上下文

- 项目根目录、项目事实源文件、临时协作文件名和项目特定启动约束由项目提示词文件指定；公共工作流文件不硬编码具体项目文件名。
- 项目提示词文件只负责声明入口、项目配置和调度引用，不作为产品需求源。
- 所有回复、文档和注释使用中文。
- 默认不提交 Git；程序员编辑的任务范围内文件默认允许执行 `git add`，但不允许 commit，除非用户明确要求提交。
- 不删除、不回滚、不覆盖无关文件；发现无关改动只报告，不处理。
- 需要删除文件、重置 Git、清理数据库或执行不可逆操作时，必须先获得用户明确确认。
- 新一轮入口开始时，主线程必须先重置本轮协作状态：对本轮子代理登记、本轮计划、本轮测试计划、程序员结果、项目启动、测试结果和浏览器测试窗口等本轮临时协作文件执行“清空内容或覆盖当前轮占位结构”；只有文件不存在时才允许创建，禁止为了重置状态删除这些协作文件后再重建。
- 重置协作文件只保留当前轮必要的空白结构或“待对应子代理生成”的占位说明；不得保留上一轮子代理 ID、上一轮测试状态、上一轮启动状态、上一轮浏览器页签状态或上一轮失败原因；不得删除 `程序员结果.md`、项目启动记录、测试结果、本轮计划或本轮测试计划等协作文件本身。
- 重置完成后，后续内容仍按需写入；只有执行到对应阶段、角色确实需要写入时才更新对应文件，主线程不得提前补写计划正文、测试项、启动细节或测试结果。
- 当前轮临时需求引用的图片属于临时输入资源，例如项目根目录临时截图或用户明确说明的本轮参考截图；测试子代理确认全部必测项通过并标记需求完成后，必须在主线程授权下删除这些临时图片，并在测试结果中记录已删除文件。正式图标、正式资源、文档长期配图或业务代码引用资源不属于临时输入资源。

## 角色边界总则

- 主线程是调度器和裁判，只负责读取入口规则、创建或复用子代理、维护写入授权、根据主线程摘要判断下一步，并做最终汇总。
- 主线程不得承担需求定位、需求识别、需求解释、需求拆解、计划生成、测试计划补写、代码修改、启动诊断、端口探测、HTTP 健康检查、浏览器验证或宿主端验证。
- 主线程给子代理的上下文只允许是文件引用、模板章节引用、任务编号、章节标题、文件范围、输出文件路径和写入授权范围；不得粘贴需求正文、计划正文、测试计划正文、启动日志、测试证据、长 diff、控制台输出或截图描述细节。
- 子代理必须根据主线程给出的文件引用自行读取所需章节和文件内容，自行完成职责内任务，并把详细结果写入指定结果文件。
- 子代理返回主线程时只允许返回 `状态：...` 和 `结果文件：...`，不在回复中展开分析、日志、diff、测试证据或文件正文。
- 主线程收到结果后默认只读取结果文件顶部 `## 主线程摘要`；只有摘要缺失、摘要冲突、需要定位责任或用户明确要求证据时，才按需读取详细记录区的相关小段。
- 需求架构子代理负责需求定位、需求拆解、本轮计划和本轮测试计划的生成或结构性更新；本轮唯一需求架构子代理必须连续处理所有未完成临时需求标题和计划/测试计划结构更新。
- 程序员子代理负责按本轮计划和分配文件范围连续修改代码、脚本、依赖、配置或工程实现，处理归属为代码实现的反馈，并把结构化结果写入程序员结果。
- 启动子代理负责启动、重启、停止、端口监听检查、HTTP 健康检查、进程状态判断和项目启动记录更新；本轮唯一启动子代理必须连续完成本轮全部启动准备和健康检查项，启动失败时必须在摘要中写清反馈对象。
- 测试子代理负责浏览器端和宿主端测试，按本轮测试计划串行执行，不拆成浏览器测试和宿主端测试两个子代理。
- 代码、脚本、端口配置、宿主入口拉起服务、依赖版本或打包装配问题必须反馈给程序员子代理；启动命令选择、运行状态刷新或启动记录问题反馈给启动子代理；用户电脑缺环境、权限、账号密钥或外部端口占用且代理无权处理时才反馈用户。

## 需求与计划规则

- 用户新增临时需求时，必须写入项目提示词文件指定的临时需求文件，每轮需求标题格式固定为一级标题 `# 时间`。
- 需求完成后，必须把对应标题改为 `# 时间-完成`；只追加 `-完成`，不要改标题时间。
- 需求架构子代理负责定位临时需求文件中所有未标记 `-完成` 的一级标题需求，并按文件从上到下连续处理；不得因为完成单个需求标题就返回主线程等待重新创建需求架构子代理。
- 主线程不能定位、识别、解释、拆解或归纳需求内容。
- 未完成需求必须先交给需求架构子代理处理，由它产出本轮计划和本轮测试计划后，再交给程序员、启动和测试子代理执行。
- 本轮计划是本轮开发参考计划，用于约束程序员子代理的任务、文件范围、依赖关系和验收口径。
- 本轮计划必须使用逐条任务清单格式，核心执行项写成 `- [ ] 任务内容。`，完成后只把对应行改成 `- [x] 任务内容。`，不要用大段叙述替代任务清单。
- 每条计划任务必须能独立判断是否完成，任务内容应写清动作、目标文件或模块、验收点；不要把多个不相干动作合并成一条。
- 程序员子代理只能执行 `- [ ]` 未完成任务；看到 `- [x]` 已完成任务不得重复执行，只能在发现回归或用户明确要求复查时反馈主线程。
- 程序员子代理接到本轮计划后，必须按清单顺序连续执行所有分配给程序员的 `[ ]` 任务；每完成一项就更新对应勾选状态并继续下一项，不因完成单项任务就返回主线程等待再次派发。
- 本轮测试计划用于约束测试子代理的测试范围、执行顺序、多状态流转、失败反馈和复测闭环。
- 本轮测试计划必须使用逐条测试清单格式，核心测试项写成 `- [ ] 测试项内容。` 或 `- [x] 测试项内容。`；`[ ]` 表示仍需测试、失败待修复、已修复待复测或阻塞未通过，`[x]` 只表示该测试项本轮已经通过且无需重复执行。
- 测试子代理只能执行本轮测试计划中 `- [ ]` 的测试项；看到 `- [x]` 已通过测试项不得重复测试，除非用户明确要求复测或程序员改动使该项相关运行状态过期。
- 本轮测试计划必须由需求架构子代理按模板产出或结构性更新；主线程不得因为文件不存在、测试即将开始或子代理阻塞而自行创建最小测试计划、补写测试项或把测试计划生成职责接回主线程。
- 主线程发现本轮测试计划不存在、为空、缺少必填测试项或明显不是需求架构子代理产物时，必须回到需求架构闸门，优先复用本轮唯一需求架构子代理重新生成；只有原需求架构子代理上下文不足、阻塞、失败、需拆分或已失效时才允许创建接力需求架构子代理。
- 不要额外全文检索或反复读取项目提示词文件；只读取公共模板、本轮需要的子代理模板。临时需求内容只从项目提示词文件指定的临时需求文件读取。
- 如果临时需求文件中的内容只是临时执行说明，不要写入正式需求源。
- 如果用户明确要求新增、修改或删除产品需求，必须先更新项目提示词文件指定的正式需求源，再评估并更新项目提示词文件指定的正式计划源，最后再落代码。
- 如果用户要求同步正式需求，需求架构子代理必须把分析出的正式产品需求写入项目提示词文件指定的正式需求源；本轮计划和本轮测试计划不能替代正式需求源。
- 同步正式需求源时，必须以当前最新需求为准；如果旧需求与本次分析结果冲突、重复或口径过期，直接删除旧冲突内容并写入最新需求，不保留历史记录、变更流水或多套并存口径。
- 如果用户要求同步正式计划，需求架构子代理必须把本次实施计划写入项目提示词文件指定的正式计划源；本轮计划只作为本轮参考计划，不能替代正式实施任务表。
- 如果本轮会修改业务代码、测试脚本、构建脚本或工程配置，必须在落代码前或落代码后同步评估正式计划源；新增任务、替换任务、废弃任务或完成已有任务都必须写入正式计划源，不能只维护本轮计划。
- 同步正式计划源时，必须与最新正式需求源对齐；如果旧计划与本次计划冲突、重复或口径过期，直接删除旧冲突任务并写入最新计划，不保留历史计划、废弃流水或多套并存任务。
- 正式需求源和正式计划源都只保存当前最新有效内容；除必要任务处理原因外，不做历史记录。
- 如果改动完成了正式计划源中已有任务，必须把对应任务从 `[ ]` 改为 `[x]`。
- 如果没有完成正式计划源中任何任务，最终回复必须说明未同步正式计划源的原因。
- 所有实现、验证和允许的计划同步完成后，测试子代理才允许把临时需求文件中对应一级标题追加 `-完成`。
- 测试子代理追加 `-完成` 前，必须检查临时需求文件、本轮计划和本轮测试计划中是否引用本轮临时图片；确认全部必测项通过后，在主线程授权下删除这些临时图片，并把删除结果写入测试结果。无法确认图片是否为临时输入资源时，不得删除，必须在测试结果中写为“待用户确认清理”。
- 程序员实现完成但测试未完成时，不得标记 `-完成`；测试完成且本轮测试计划中所有必测项通过后，由测试子代理更新标题追加 `-完成`。
- 未完成、未验证或仍有阻塞项时，不得把需求标题标记为 `-完成`。

## 启动与运行约束

- 项目具体启动方式、端口、宿主入口、是否允许直接运行服务入口等规则由项目提示词文件指定。
- 启动项目的子代理必须创建或更新项目启动记录。
- 启动子代理接到本轮启动任务后，必须连续完成启动、重启、端口监听、HTTP 健康检查、进程状态判断和启动记录更新；不得因为完成单个端口或单个客户端检查就返回主线程等待重新创建启动子代理。
- 启动、重启、停止、端口监听检查、HTTP 健康检查、进程状态判断、项目启动状态更新都属于启动子代理职责；主线程不得直接执行 PowerShell、curl、浏览器探测或其他命令来确认前端端口、服务端口或宿主进程运行状态。
- 项目启动记录至少写明：启动方式、使用的命令或 IDE Run Configuration、实际访问 URL、服务是否由宿主入口拉起、端口、关键日志位置、测试前置状态和停止方式。
- 如果用户明确要求“不测试、不构建”，所有代理只能做静态自查，不运行测试和构建命令。

## 子代理通用约束

- 子代理必须先读取公共模板，再读取自己的角色模板。
- 子代理只读取完成任务所需的最小文件范围，不要全文读取无关目录。
- 子代理只能处理主线程分配的明确任务，不创建下级子代理。
- 子代理接收任务时，主线程只提供文件路径、章节引用、任务编号、文件范围、输出文件路径、写入授权和状态要求，不在消息中粘贴文件正文、长日志、长 diff、测试细节或截图描述。
- 子代理必须自行读取主线程提供的文件引用和章节引用；如果引用缺失、文件不存在或章节不明确，先返回阻塞并写入结果文件，不要求主线程粘贴正文。
- 子代理的详细产出必须写入对应结果文件；返回主线程时只汇报结果文件路径和状态，状态只允许使用 `完成`、`阻塞`、`失败`、`需复测` 或 `需拆分`。
- 子代理默认只能写自己负责的结果文件和主线程明确授权的业务文件；没有共享文件写入授权时，不得修改临时需求文件、本轮计划、本轮测试计划、项目启动记录、正式需求源、正式架构源、正式计划源或项目提示词文件。
- 子代理需要更新共享文件时，必须在结果文件中写明建议更新内容和目标位置，由主线程确认当前没有其他写入者后再授权写入或由主线程串行合并。
- 子代理默认不能修改正式需求源；但需求架构子代理在主线程明确分配“同步正式需求”任务时，必须按最新需求分析结果更新正式需求源。
- 子代理默认不能修改正式计划源；但需求架构子代理在主线程明确分配“同步正式计划”任务时，必须按最新本次计划更新正式计划源。
- 子代理不能跨任务顺手重构无关文件。
- 子代理不能提交 commit、推送、变基或回滚；程序员子代理只允许对自己任务范围内已经编辑的文件执行 `git add`，不得暂存无关文件。
- 子代理返回结果后，主线程必须及时关闭该子代理，避免已完成会话继续占用资源或残留上下文。
- 测试截图只允许作为工具即时观察结果使用，默认不保存到仓库或本地文件；失败截图也不保留。
- 如果验证工具强制生成了截图文件，创建该文件的子代理必须在本轮输出前删除；无法确认来源或无法删除时，必须在结果中列为“待用户确认清理”，不得继续扩散引用。
- 如果本轮需求、计划或测试计划引用了临时图片，负责最终通过和完成标记的测试子代理必须把图片清理纳入收尾；只允许删除已确认属于本轮临时输入的图片，不得删除正式图标、业务资源、文档长期配图或无法确认来源的图片。
- 子代理必须把关键可见现象、页面状态、控制台错误、网络错误和复现步骤写入对应结果文件；返回主线程时仍只汇报结果文件路径和状态，不用截图文件作为长期证据。
