# 公共模板

## 新窗口任务公共入口规则

### 主线程读取边界

- 读取：项目提示词文件。
- 读取：`多代理工作流` 中的公共模板。
- 读取：主线程调度模板。
- 读取：当前需要创建的角色模板。
- 读取：主线程可以读取项目提示词文件指定的临时需求文件，用于实时确认需求和维护一级标题状态。
- 禁止：不读取项目提示词文件指定的项目规则正文。
- 禁止：不读取正式需求源、正式架构源或正式计划源正文。
- 禁止：不读取本轮计划或本轮测试计划正文。
- 禁止：不读取程序员结果、项目启动记录或测试结果正文。
- 禁止：不读取浏览器测试窗口记录正文。
- 禁止：不接管子代理判断。
- 归属：本轮临时需求只来自项目提示词文件指定的临时需求文件。
- 归属：`-编写中` 或无状态标题表示用户仍在编辑，主线程和子代理都不得处理其正文。
- 归属：只有显式 `-待确认` 标题由主线程在当前对话框中与用户实时确认或头脑风暴。
- 归属：`-已确认` 且未 `-完成` 标题由计划编排子代理读取并生成本轮计划和本轮测试计划。
- 冻结：`-已确认` 标题正文不得修改；用户需要补充或改动时，必须新增一个新的 `# 时间-编写中` 或 `# 时间-待确认` 标题。
- 回写：主线程确认或头脑风暴后可以用确认后的正文覆盖临时需求正文；覆盖前必须提取原需求正文和本次确认对话中的图片引用。
- 回写：覆盖后的确认正文必须自然体现这些图片引用，不能新增固定图片清理小节，也不能把图片引用移出需求正文。
- 顺序：依次执行主线程需求确认、计划编排、程序员和测试。
- 禁止：不再创建检验子代理。
- 复用：每阶段默认按职责复用同角色子代理；计划编排保持唯一，程序员和测试只有在计划明确并行组时允许条件并行。
- 例外：上下文不足、阻塞、失败、需拆分或已失效时才接力。
- 闸门：“全量测试”“只用浏览器测试”“验证”或“测试”入口也必须先过计划编排闸门。
- 禁止：不得因看起来只是测试就跳过主线程需求确认、计划编排或程序员阶段。
- 范围：测试入口只限制最终测试范围，不改变主线程调度身份和阶段顺序。
- 禁止：“只执行浏览器端验证”不等于主线程亲自测试、立即创建测试子代理或跳过未完成编码修复。

### 新窗口闸门

- 归属：上一轮本轮计划只属于上一轮固化记忆。
- 归属：上一轮本轮测试计划只属于上一轮固化记忆。
- 归属：上一轮项目启动和测试结果只属于上一轮固化记忆。
- 禁止：上一轮固化记忆不代表当前轮可执行状态。
- 禁止：上一轮计划摘要写着“可进入测试”也不能跳过本闸门。
- 触发：新一轮入口。
- 归属：计划编排子代理读取上一轮固化文件。
- 归属：主线程读取当前临时需求文件并处理标题状态。
- 完成口径：不存在需要处理的 `-编写中` 或无状态标题。
- 完成口径：不存在显式 `-待确认` 标题；如存在，主线程先与用户实时确认或头脑风暴，覆盖回写确认正文并确保图片引用仍在正文中体现后，再把标题改为 `-已确认`。
- 完成口径：整合生成新的本轮计划。
- 完成口径：整合生成新的本轮测试计划。
- 禁止：存在未确认需求时，不生成新的本轮计划或本轮测试计划。
- 变化：用户中途追加无状态、`-编写中` 或 `-待确认` 标题时，回到主线程需求状态闸门，不继续派发计划编排。
- 禁止：新的计划编排闸门通过前，不创建测试子代理。
- 范围：“全量测试”最终覆盖浏览器端和宿主端。
- 范围：“只用浏览器测试”只覆盖浏览器端，不执行宿主端测试项。
- 禁止：任何入口都不能跳过主线程需求确认、计划编排和程序员闸门。
- 闸门：摘要显示存在程序员未完成任务时，先按计划编排子代理给出的串行任务或程序员并行组创建或复用程序员子代理。
- 执行：未标记并行组的程序员任务按清单顺序连续完成。
- 并行：只有计划编排子代理明确标记为同一程序员并行组的任务，才允许创建多个程序员子代理条件并行。
- 禁止：程序员阶段未完成前，不创建测试子代理。
- 串行：计划编排阶段、程序员阶段和测试阶段仍按阶段串行推进；阶段内部只有明确并行组时才允许条件并行。
- 限制：除计划编排明确授权的程序员并行组外，同一时刻只允许一个本轮子代理运行。
- 禁止：不并行创建计划编排子代理。
- 禁止：未标记程序员并行组时，不并行创建多个程序员子代理。
- 禁止：未标记测试并行组时，不并行创建多个测试子代理。
- 禁止：不按单个需求、计划项、启动检查项或测试项逐项新建同角色子代理。
- 测试：默认同一轮只创建一个测试子代理。
- 测试：未标记测试并行组时，按本轮测试计划串行验证指定范围并持续更新测试状态。

### 程序员条件并行

- 来源：程序员并行组只能由计划编排子代理在本轮计划中明确标记。
- 条件：并行任务之间不得存在顺序依赖。
- 条件：并行任务写入文件范围不得重叠；共享协议、共享状态、数据库 schema、API 客户端、构建脚本和同一服务入口默认视为冲突范围。
- 条件：并行任务不得同时重启、停止、启动或健康检查同一个宿主、服务或端口。
- 条件：当前不存在无状态、`-编写中` 或 `-待确认` 的需求标题。
- 载荷：每个并行程序员子代理只接收自己的任务编号、文件范围、写入授权和结果章节要求。
- 写入：`程序员结果.md` 保持单文件，按任务编号或并行组编号分章节写入。
- 写入：同一时间只允许一个程序员子代理获得 `程序员结果.md` 写入授权。
- 写入：同一时间只允许一个程序员子代理获得 `本次计划.md` 写入授权。
- 禁止：并行程序员子代理不得覆盖其他任务章节、主线程摘要、其他子代理结果或整个程序员结果文件。
- 收尾：并行组全部完成或出现阻塞后，主线程再读取 `程序员结果.md` 的 `## 主线程摘要` 和各任务章节摘要决定下一步。

### 测试条件并行

- 来源：测试并行组只能由计划编排子代理在本轮测试计划中明确标记。
- 条件：并行测试项之间不得存在顺序依赖。
- 条件：并行测试项不得共享同一个浏览器页签、桌面宿主窗口、服务启动/重启动作、端口状态变更、数据库写入状态或需要连续操作的业务流程。
- 条件：静态检查、互不依赖的接口检查、不同页面的只读浏览器验证或不同宿主范围的只读检查才允许进入测试并行组。
- 条件：当前不存在无状态、`-编写中` 或 `-待确认` 的需求标题。
- 载荷：每个并行测试子代理只接收自己的测试项编号、验证端、浏览器页签范围、宿主范围、写入授权和结果章节要求。
- 写入：`测试结果.md` 保持单文件，按测试项编号或并行组编号分章节写入。
- 写入：同一时间只允许一个测试子代理获得 `测试结果.md` 写入授权。
- 写入：同一时间只允许一个测试子代理获得 `本次测试计划.md` 写入授权。
- 写入：同一时间只允许一个测试子代理获得 `浏览器测试窗口.md` 写入授权。
- 禁止：并行测试子代理不得覆盖其他测试项章节、主线程摘要、其他子代理结果或整个测试结果文件。
- 禁止：并行测试子代理不得追加临时需求标题 `-完成`，不得执行临时图片最终清理。
- 收尾：并行组全部完成或出现阻塞后，主线程创建或复用唯一测试收口子代理，重新读取完整本轮测试计划，统一处理复测、完成标记和临时图片清理。

### 中途新增需求闸门

- 写入：用户中途新增需求时，必须写入临时需求文件的新一级标题。
- 禁止：不得修改已确认或已完成的旧需求正文来表达新增需求。
- 状态：新增标题无状态或为 `-编写中` 时，表示用户仍在编写，主线程和子代理都不得处理正文。
- 状态：新增标题显式改为 `-待确认` 后，主线程才在当前对话框中实时确认。
- 写入：确认后由主线程把新增标题改为 `-已确认`。
- 决策：新增需求是否并入当前轮，只能由计划编排子代理读取已确认需求后判断并写入本轮计划和本轮测试计划。
- 回写：新增需求经主线程确认并覆盖回写时，必须确保原需求和确认对话中的图片引用仍在确认正文中体现。
- 计划编排阶段：计划编排尚未完成时，复用原计划编排子代理重新整合全部 `-已确认` 且未 `-完成` 的标题。
- 程序员阶段：程序员正在执行时，程序员完成当前最小计划项后停止继续后续计划项，写入程序员结果，再回到计划编排子代理更新本轮计划和本轮测试计划。
- 测试阶段：测试正在执行时，测试子代理完成当前测试项后停止；如果新增需求影响当前轮实现，回到计划编排子代理；如果新增需求明确作为下一轮，则当前测试可继续且新增需求不进入当前轮。
- 禁止：程序员子代理和测试子代理不得自行读取、解释、合并或实现中途新增需求。
- 范围：具体测试范围以本轮测试计划和当前任务场景说明为准。

## 共同上下文

- 项目根目录、项目事实源文件、临时协作文件名和项目特定启动约束由项目提示词文件指定；公共工作流文件不硬编码具体项目文件名。
- 项目提示词文件只负责声明入口、项目配置和调度引用，不作为产品需求源。
- 所有回复、文档和注释使用中文。
- 默认不提交 Git；程序员编辑的任务范围内文件默认允许执行 `git add`，但不允许 commit，除非用户明确要求提交。
- 不删除、不回滚、不覆盖无关文件；发现无关改动只报告，不处理。
- 需要删除文件、重置 Git、清理数据库或执行不可逆操作时，必须先获得用户明确确认。

### 固化文件规则

- 范围：本轮计划是固化协作文件。
- 范围：本轮测试计划是固化协作文件。
- 范围：程序员结果、项目启动记录和测试结果是固化协作文件。
- 范围：浏览器测试窗口记录是固化协作文件。
- 范围：本轮子代理登记是固化协作文件。
- 定义：“清空”“重置”“覆盖生成”只表示保留原路径和文件本身。
- 允许：清空文件内容。
- 允许：用当前轮占位结构覆盖内容。
- 禁止：删除文件后再创建同名文件。
- 禁止：用移动、删除、重命名或临时文件替换实现清空。

### 新一轮固化文件边界

- 禁止：主线程不读取上一轮本轮计划正文或 `## 主线程摘要`。
- 禁止：主线程不读取上一轮本轮测试计划正文或 `## 主线程摘要`。
- 禁止：主线程不读取程序员结果、项目启动或测试结果正文。
- 禁止：主线程不自行提取续接摘要。
- 禁止：主线程不判断上一轮是否通过。
- 禁止：主线程不重置这些协作文件内容。
- 禁止：主线程不根据上一轮状态派发程序员、启动或测试子代理。
- 处理：主线程只能登记本轮计划编排子代理。
- 载荷：当前临时需求文件路径。
- 载荷：上一轮固化协作文件路径。
- 载荷：当前本轮计划路径。
- 载荷：当前本轮测试计划路径。
- 载荷：写入授权。

### 浏览器窗口记录边界

- 禁止：`浏览器测试窗口.md` 不属于需求续接记忆。
- 禁止：不交给计划编排子代理读取或整合。
- 归属：只由测试子代理按需读取和更新。
- 用途：复用浏览器测试专用页签。
- 用途：避免每次浏览器验证都打开新窗口或误操作用户当前页面。
- 阻塞口径：文件缺失时，测试子代理先反馈 `固化协作文件缺失：浏览器测试窗口记录`。
- 禁止：测试子代理不得自行删除后重建。
- 禁止：测试子代理不得静默新建记录文件。
- 归属：上一轮测试结果是否通过由计划编排子代理判断。
- 归属：上一轮计划完成项和失败复测项由计划编排子代理判断。
- 归属：“程序员完成但测试未完成”由计划编排子代理整合。
- 禁止：主线程不得代替计划编排子代理读取、归纳或裁剪这些内容。

### 计划编排先整合

- 触发：主线程完成临时需求标题状态检查。
- 禁止：存在无状态、`-编写中` 或 `-待确认` 标题时，不覆盖生成本轮计划。
- 禁止：存在无状态、`-编写中` 或 `-待确认` 标题时，不覆盖生成本轮测试计划。
- 变化：确认后如果临时需求文件新增无状态、`-编写中` 或 `-待确认` 标题，必须回到主线程需求状态闸门。
- 触发：计划编排子代理完成上一轮固化文件整合。
- 触发：计划编排子代理完成当前已确认且未完成需求整合。
- 允许：在授权范围内覆盖生成新的本轮计划。
- 允许：在授权范围内覆盖生成新的本轮测试计划。
- 禁止：主线程不得在计划编排子代理之前清空或覆盖本轮计划。
- 禁止：主线程不得在计划编排子代理之前清空或覆盖本轮测试计划。
- 禁止：主线程不得在计划编排子代理之前清空或覆盖程序员结果、项目启动、测试结果或浏览器测试窗口记录。
- 完成口径：当前轮计划和测试计划已经由计划编排子代理生成。
- 写入：后续角色按各自授权更新对应文件。

### 临时图片清理边界

- 定义：主线程确认或头脑风暴后回写到临时需求正文中的图片引用，默认属于当前轮临时输入资源。
- 定义：不使用固定图片清理小节，不把图片引用复制到本轮测试计划；图片引用必须留在临时需求正文中。
- 定义：测试子代理最终重新读取临时需求文件对应标题正文，扫描其中图片引用并执行清理。
- 示例：项目根目录临时截图。
- 示例：用户明确说明的本轮参考截图。
- 触发：测试子代理确认全部必测项通过并标记需求完成。
- 写入：在主线程授权下删除这些临时图片。
- 写入：在测试结果中记录已删除文件。
- 允许：删除临时需求正文中引用的本轮临时输入图片前不再单独询问用户。
- 阻塞：临时需求确认正文中缺失主线程确认前已存在或确认对话中出现过的图片引用时，不得继续计划编排或测试收尾，必须回到主线程需求确认回写。
- 禁止：正式图标不属于临时输入资源。
- 禁止：正式资源不属于临时输入资源。
- 禁止：文档长期配图或业务代码引用资源不属于临时输入资源。

## 角色边界总则

### 主线程角色

- 职责：读取入口规则、创建或复用子代理、维护写入授权。
- 职责：根据主线程摘要判断下一步并做最终汇总。
- 定义：“主线程摘要”只指子代理返回消息中的状态和结果文件路径。
- 定义：也可指结果文件中极短的 `## 主线程摘要` 区。
- 禁止：不为生成摘要而读取项目事实源或固化协作文件正文。
- 职责：主线程负责读取临时需求文件；无状态和 `-编写中` 只等待用户继续编写，显式 `-待确认` 才与用户实时确认或头脑风暴，并覆盖回写确认正文，确保图片引用仍在正文中体现后，把确认后的标题标为 `-已确认`。
- 禁止：除需求实时确认外，不承担计划生成或测试计划补写。
- 禁止：不承担代码修改、启动诊断、端口探测、HTTP 健康检查、浏览器验证或宿主端验证。

### 问题回流边界

- 触发：用户指出的问题。
- 触发：流程缺陷或子代理遗漏。
- 触发：计划未完成或测试计划未完成。
- 触发：测试未收尾、完成标记缺失或临时图片未清理。
- 禁止：主线程不得读取需求、计划、测试计划、启动记录或测试结果正文直接判断和修复。
- 处理：主线程只记录问题现象。
- 载荷：文件路径、问题描述、写入授权和期望状态要求。
- 派回：对应子代理。

### 归属规则

- 派回：需求、计划、测试计划结构缺陷给计划编排子代理。
- 派回：代码、脚本、配置、实现遗漏给程序员子代理。
- 派回：启动、端口、宿主、健康状态缺陷给程序员子代理。
- 派回：测试执行、复测、测试计划状态、完成标记和临时图片清理给测试子代理。
- 派回：用户电脑缺环境、权限、账号密钥或外部端口占用且代理无权处理时才反馈用户。

### 子代理上下文

- 载荷：文件引用、模板章节引用、任务编号、章节标题和文件范围。
- 载荷：输出文件路径和写入授权范围。
- 禁止：不粘贴需求、计划、测试计划正文。
- 禁止：不粘贴启动日志、测试证据、长 diff、控制台输出或截图描述细节。
- 执行：子代理自行读取所需章节和文件内容。
- 写入：详细结果写入指定结果文件。
- 返回：只允许 `状态：...` 和 `结果文件：...`。
- 禁止：返回主线程时不展开分析、日志、diff、测试证据或文件正文。

### 角色职责

- 计划编排：读取 `-已确认` 且未 `-完成` 的需求，生成或结构性更新本轮计划和本轮测试计划。
- 计划编排：不得确认、改写、补写、删除、重排或冻结临时需求标题和正文。
- 计划编排：不得提取图片引用生成独立清理清单；图片引用清理依据保留在临时需求正文中。
- 程序员：按本轮计划和文件范围修改实现；默认串行，只有计划编排明确标记的程序员并行组允许条件并行。
- 程序员：负责启动、重启、停止、端口监听、健康检查、进程状态和项目启动记录，并写入程序员结果。
- 测试：浏览器端和宿主端测试；默认按本轮测试计划串行执行，只有计划编排明确标记的测试并行组允许条件并行。
- 禁止：测试不按浏览器端和宿主端机械拆成两个子代理；只能按测试计划中的测试并行组拆分。

## 需求与计划规则

### 临时需求

- 写入：用户新增临时需求进入项目提示词文件指定的临时需求文件。
- 格式：每轮需求标题固定为一级标题 `# 时间-状态`。
- 状态：`-编写中` 表示用户仍在编辑，主线程和子代理都不读取正文做判断。
- 状态：`-待确认` 表示可以由主线程在当前对话框中实时确认。
- 状态：无状态标题等同 `-编写中`。
- 状态：`-已确认` 表示需求正文冻结，可以交给计划编排子代理读取。
- 状态：`-已确认-完成` 表示测试收尾已完成。
- 冻结：`-已确认` 和 `-已确认-完成` 标题正文禁止修改。
- 修改：用户需要变更已确认需求时，必须新增一个新的 `# 时间-编写中` 或 `# 时间-待确认` 标题。
- 归属：主线程负责与用户确认或头脑风暴显式 `-待确认` 标题，并在覆盖回写确认正文时确保图片引用仍在正文中体现，最后把标题改为 `-已确认`。
- 归属：计划编排子代理只定位所有 `-已确认` 且未 `-完成` 的一级标题需求。
- 连续：按文件从上到下连续处理。

### 本轮计划

- 用途：约束程序员子代理任务、文件范围、依赖关系和验收口径。
- 格式：执行项使用 `- [ ]` 和 `- [x]` 逐条清单。
- 格式：如允许程序员条件并行，必须写明 `并行组`、任务编号、文件范围、依赖关系和写入冲突边界。
- 完成：程序员子代理每完成一个计划项，必须立即把对应行改为 `[x]`，并同步必要完成摘要、阻塞原因或未完成原因。
- 要求：每条任务可独立判断完成。
- 要求：写清动作、目标文件或模块、验收点。
- 禁止：不把多个不相干动作合并成一条。
- 禁止：程序员子代理不重复执行 `[x]` 任务，除非发现回归或用户明确复查。
- 禁止：程序员子代理不得等阶段末尾批量更新本轮计划。
- 连续：程序员子代理按清单顺序连续执行所有分配任务。

### 本轮测试计划

- 用途：约束测试范围、执行顺序、多状态流转、失败反馈和复测闭环。
- 格式：测试项使用 `- [ ]` 和 `- [x]` 逐条清单。
- 格式：如允许测试条件并行，必须写明 `测试并行组`、测试项编号、验证端、依赖关系、浏览器页签范围、宿主范围和写入冲突边界。
- 定义：`[ ]` 表示待测试、待修复、待复测或阻塞未通过。
- 定义：`[x]` 只表示本轮已通过且无需重复执行。
- 写入：测试子代理每完成一个测试项，必须立即更新对应清单和详情状态；通过才改为 `[x]`，失败、阻塞或待复测保持 `[ ]` 并写清原因。
- 禁止：测试子代理不重复执行 `[x]` 测试项，除非用户要求复测或相关运行状态过期。
- 禁止：测试子代理不得等阶段末尾批量更新本轮测试计划。
- 禁止：并行测试子代理不得执行完成标记、临时图片最终清理或整轮完成判断。
- 归属：测试计划必须由计划编排子代理产出或结构性更新。
- 禁止：主线程不自行创建最小测试计划或补写测试项。
- 派回：测试计划缺失、为空或结构不合格时，回到计划编排闸门。

### 正式文档同步

- 禁止：临时执行说明不写入正式需求源。
- 闸门：用户明确要求新增、修改或删除产品需求时，先更新正式需求源。
- 写入：正式需求变更后评估并更新正式计划源。
- 禁止：本轮计划和本轮测试计划不能替代正式需求源。
- 口径：正式需求源和正式计划源只保存当前最新有效内容。
- 处理：删除冲突、重复或过期旧内容。
- 禁止：不保留历史记录、变更流水或多套并存口径。
- 写入：完成正式计划源已有任务时，把对应任务从 `[ ]` 改为 `[x]`。
- 说明：未完成正式计划源任务时，最终回复说明未同步原因。

### 完成标记闸门

- 闸门：所有实现、验证和允许的计划同步完成后，测试子代理才允许追加 `-完成`。

### 完成标记前置检查

- 触发：测试子代理准备追加 `-完成`。
- 读取：重新读取临时需求文件中对应已确认标题正文，扫描其中图片引用。
- 完成口径：全部必测项通过。
- 写入：在主线程授权下删除临时需求正文中引用的本轮临时输入图片，无需再次确认。
- 写入：把删除结果写入测试结果。
- 禁止：无法确认图片是否为临时输入资源时，不得删除。
- 写入：无法确认时，在测试结果中写为“待用户确认清理”。
- 禁止：不得误删正式图标、业务资源、文档长期配图或无法确认来源的图片。

### 测试收尾硬闸门

- 触发：测试子代理完成全部必测项通过。
- 读取：重新读取完整本轮测试计划。
- 完成口径：全部必测项清单均为 `[x]`。
- 完成口径：详情状态均为 `通过`。
- 写入：在主线程授权下把临时需求文件对应一级标题追加 `-完成`。
- 处理：重新读取临时需求文件对应标题正文，扫描并删除本轮临时图片引用。
- 处理：正文中引用的本轮临时输入图片直接删除，不再向用户确认。
- 写入：把删除、无法确认或无需删除的结果写入测试结果。
- 阻塞口径：任一收尾步骤未完成。
- 禁止：收尾未完成时，测试子代理不得返回 `状态：完成`。
- 程序员实现完成但测试未完成时，不得标记 `-完成`；测试完成且本轮测试计划中所有必测项通过后，由测试子代理更新标题追加 `-完成`。
- 未完成、未验证或仍有阻塞项时，不得把需求标题标记为 `-完成`。

## 启动与运行约束

- 项目具体启动方式、端口、宿主入口、是否允许直接运行服务入口等规则由项目提示词文件指定。
- 程序员子代理负责启动项目和维护项目启动记录；项目启动记录缺失时必须先反馈 `固化协作文件缺失：项目启动记录`，不得自行删除后重建或静默新建记录文件。
- 程序员子代理接到本轮启动准备任务后，必须连续完成启动、重启、端口监听、HTTP 健康检查、进程状态判断和启动记录更新；不得因为完成单个端口或单个客户端检查就返回主线程等待重新创建子代理。
- 启动、重启、停止、端口监听检查、HTTP 健康检查、进程状态判断、项目启动状态更新都属于程序员子代理职责；主线程不得直接执行 PowerShell、curl、浏览器探测或其他命令来确认前端端口、服务端口或宿主进程运行状态。
- 项目启动记录至少写明：启动方式、使用的命令或 IDE Run Configuration、实际访问 URL、服务是否由宿主入口拉起、端口、关键日志位置、测试前置状态和停止方式。
- 如果用户明确要求“不测试、不构建”，所有代理只能做静态自查，不运行测试和构建命令。

## 子代理通用约束

- 子代理必须先读取公共模板，再读取自己的角色模板。
- 子代理只读取完成任务所需的最小文件范围，不要全文读取无关目录。
- 子代理只能处理主线程分配的明确任务，不创建下级子代理。
- 子代理接收任务时，主线程只提供文件路径、章节引用、任务编号、文件范围、输出文件路径、写入授权和状态要求，不在消息中粘贴文件正文、长日志、长 diff、测试细节或截图描述。
- 子代理必须自行读取主线程提供的文件引用和章节引用；如果引用缺失、文件不存在或章节不明确，先返回阻塞并写入结果文件，不要求主线程粘贴正文。
- 子代理的详细产出必须写入对应结果文件；返回主线程时只汇报结果文件路径和状态，状态只允许使用 `完成`、`阻塞`、`失败`、`需复测` 或 `需拆分`。
- 子代理默认只能写自己负责的结果文件和主线程明确授权的业务文件；没有共享文件写入授权时，不得修改临时需求文件、本轮计划、本轮测试计划、项目启动记录、正式需求源、正式架构源、正式计划源或项目提示词文件。
- 子代理写入任何固化协作文件时，只能编辑已有文件内容；如果文件不存在，必须先在结果文件中反馈“固化协作文件缺失”，等待主线程或用户确认创建，不得自行删除后重建，也不得把“清空”理解为删除文件。
- 子代理需要更新共享文件时，必须在结果文件中写明建议更新内容和目标位置，由主线程确认当前没有其他写入者后再授权写入或由主线程串行合并。
- 子代理默认不能修改正式需求源；但计划编排子代理在主线程明确分配“同步正式需求”任务时，必须按最新需求分析结果更新正式需求源。
- 子代理默认不能修改正式计划源；但计划编排子代理在主线程明确分配“同步正式计划”任务时，必须按最新本次计划更新正式计划源。
- 子代理不能跨任务顺手重构无关文件。
- 子代理不能提交 commit、推送、变基或回滚；程序员子代理只允许对自己任务范围内已经编辑的文件执行 `git add`，不得暂存无关文件。
- 子代理返回结果后，主线程必须及时关闭该子代理，避免已完成会话继续占用资源或残留上下文。
- 测试截图只允许作为工具即时观察结果使用，默认不保存到仓库或本地文件；失败截图也不保留。
- 如果验证工具强制生成了截图文件，创建该文件的子代理必须在本轮输出前删除；无法确认来源或无法删除时，必须在结果中列为“待用户确认清理”，不得继续扩散引用。
- 如果临时需求正文记录了图片引用，负责最终通过和完成标记的测试子代理必须重新读取该正文并把其中本轮临时输入图片纳入收尾直接删除；不得删除正式图标、业务资源、文档长期配图或无法确认来源的图片。
- 子代理必须把关键可见现象、页面状态、控制台错误、网络错误和复现步骤写入对应结果文件；返回主线程时仍只汇报结果文件路径和状态，不用截图文件作为长期证据。
