# 多代理工作流提示词说明

本目录保存可复用的多代理工作流提示词。它只描述公共流程、角色边界、交接方式和结果文件格式，不保存具体项目的事实源文件名、端口、启动命令、宿主规则或业务需求。

## 文件说明

- `00-公共模板.md`：所有角色共同遵守的基础规则，包括阶段顺序、共享文件写入、需求与计划规则、启动与测试边界。
- `01-主线程调度模板.md`：主线程调度规则，包括唯一同角色子代理、串行阶段闸门、共享文件写入授权和闭环回流。
- `10-需求架构子代理提示词.md`：需求定位、需求拆解、本轮计划和本轮测试计划生成规则。
- `20-程序员子代理提示词.md`：程序员子代理连续执行本轮计划、写入程序员结果和反馈复测规则。
- `30-启动子代理提示词.md`：启动、重启、端口检查、健康检查和项目启动记录规则。
- `40-测试子代理提示词.md`：浏览器端、宿主端测试、测试结果记录和完成标记规则。

## 使用方式

1. 在项目根目录保留一个项目提示词文件，文件名由具体项目自行决定。
2. 在项目提示词文件中声明当前项目配置，包括项目规则文件、正式需求源、正式架构源、正式计划源、临时需求文件、本轮计划、本轮测试计划、程序员结果、项目启动记录、测试结果和浏览器测试窗口记录。
3. 在项目提示词文件中声明当前项目特定规则，例如端口、启动入口、是否允许直接运行服务、测试目录和不测试的端。
4. 在入口命令中要求主线程先读取项目提示词文件，再读取本目录中的公共模板和主线程调度模板。
5. 创建子代理时，只引用对应角色提示词文件，不复制公共模板正文、项目事实源正文或长日志。

## 迁移到其他项目

迁移时复制整个 `多代理工作流/` 目录即可。新项目需要单独创建或改写自己的项目提示词文件，并至少补齐以下内容：

- 项目规则文件。
- 正式需求源。
- 正式架构源。
- 正式计划源。
- 临时需求文件。
- 本轮计划。
- 本轮测试计划。
- 本轮子代理登记。
- 程序员结果。
- 项目启动记录。
- 测试结果。
- 浏览器测试窗口记录。
- 项目特定启动、端口、测试和宿主约束。

不要把具体项目的规则文件名、需求文件名、架构文件名、计划文件名、端口、目录结构或宿主规则写入本目录。此类内容属于项目提示词文件。

## 协作文件处理规则

本轮协作文件是跨角色共享的状态文件，包括本轮子代理登记、本轮计划、本轮测试计划、程序员结果、项目启动记录、测试结果和浏览器测试窗口记录。

新一轮开始时只能清空这些文件内容或覆盖为当前轮占位结构；如果文件不存在，才允许创建。不得为了重置状态删除这些文件后再重建，避免触发误删、丢失文件权限、丢失编辑器关联或造成子代理误判文件不存在。

临时截图、一次性交接文件等明确临时资源不属于上述协作文件。它们只能按对应模板中的授权规则清理。
