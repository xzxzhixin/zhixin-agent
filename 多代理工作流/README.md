# 多代理工作流提示词说明

本目录保存可复用的多代理工作流提示词。它只描述公共流程、角色边界、交接方式和结果文件格式，不保存具体项目的事实源文件名、端口、启动命令、宿主规则或业务需求。

## 文件说明

- `00-公共模板.md`：所有角色共同遵守的基础规则，包括阶段顺序、共享文件写入、需求与计划规则、启动与测试边界。
- `01-主线程调度模板.md`：主线程调度规则，包括计划编排唯一、程序员条件并行、测试条件并行、串行阶段闸门、共享文件写入授权和闭环回流。
- `10-计划编排子代理提示词.md`：读取已确认需求、生成本轮计划和本轮测试计划规则。
- `20-程序员子代理提示词.md`：程序员子代理连续执行本轮计划、启动准备、端口检查、健康检查、项目启动记录、写入程序员结果和反馈复测规则。
- `40-测试子代理提示词.md`：浏览器端、宿主端测试、测试结果记录和完成标记规则。

## 使用方式

1. 在项目根目录保留一个项目提示词文件，文件名由具体项目自行决定。
2. 在项目提示词文件中声明当前项目配置，包括项目规则文件、正式需求源、正式架构源、正式计划源、临时需求文件、本轮计划、本轮测试计划、程序员结果、项目启动记录、测试结果和浏览器测试窗口记录。
3. 在项目提示词文件中声明当前项目特定规则，例如端口、启动入口、是否允许直接运行服务、测试目录和不测试的端。
4. 在入口命令中要求主线程先读取项目提示词文件，再读取本目录中的公共模板和主线程调度模板。
5. 创建子代理时，只引用对应角色提示词文件，不复制公共模板正文、项目事实源正文或长日志。

## 迁移到其他项目

迁移时复制整个 `多代理工作流/` 目录即可。新项目需要单独创建或改写自己的项目提示词文件，并至少补齐以下内容：

- 项目规则文件。
- 正式需求源。
- 正式架构源。
- 正式计划源。
- 临时需求文件。
- 本轮计划。
- 本轮测试计划。
- 本轮子代理登记。
- 程序员结果。
- 项目启动记录。
- 测试结果。
- 浏览器测试窗口记录。
- 项目特定启动、端口、测试和宿主约束。

不要把具体项目的规则文件名、需求文件名、架构文件名、计划文件名、端口、目录结构或宿主规则写入本目录。此类内容属于项目提示词文件。

## 协作文件处理规则

### 程序员条件并行

- 默认：程序员任务默认串行执行。
- 例外：只有本轮计划明确标记程序员并行组时，才允许多个程序员子代理条件并行。
- 写入：`程序员结果.md` 始终保持单文件，按任务编号或并行组编号分章节写入。
- 写入：`本次计划.md`、`程序员结果.md` 和 `项目启动.md` 的写入必须由主线程串行授权。
- 禁止：并行程序员子代理不得覆盖其他任务章节、其他并行组章节或主线程摘要。

### 测试条件并行

- 默认：测试任务默认串行执行。
- 例外：只有本轮测试计划明确标记测试并行组时，才允许多个测试子代理条件并行。
- 写入：`测试结果.md` 始终保持单文件，按测试项编号或并行组编号分章节写入。
- 写入：`本次测试计划.md`、`测试结果.md` 和 `浏览器测试窗口.md` 的写入必须由主线程串行授权。
- 禁止：并行测试子代理不得覆盖其他测试项章节、其他并行组章节或主线程摘要。
- 收口：并行测试子代理不得追加 `-完成` 或清理临时图片；并行组收敛后由唯一测试收口子代理统一完成。

### 文件范围

- 范围：本轮子代理登记。
- 范围：本轮计划。
- 范围：本轮测试计划。
- 范围：程序员结果。
- 范围：项目启动记录。
- 范围：测试结果。
- 范围：浏览器测试窗口记录。
- 归属：浏览器测试窗口记录由测试子代理专属维护。
- 用途：只用于复用浏览器测试专用页签。
- 禁止：浏览器测试窗口记录不参与计划编排续接整合。

### 固化文件不删除重建

- 要求：固化协作文件必须保留文件本身。
- 定义：“清空”“重置”“覆盖生成”“刷新记录”只表示保留原路径。
- 允许：替换文件内容。
- 允许：按章节更新。
- 禁止：不得删除后重建。
- 禁止：不得移动、重命名或用临时文件替换。

### 新窗口闸门

- 触发：新一轮开始。
- 允许：主线程只能重置本轮子代理登记文件。
- 禁止：主线程不能读取上一轮协作文件正文。
- 禁止：主线程不能读取上一轮 `## 主线程摘要`。
- 禁止：主线程不能清空本轮计划或本轮测试计划。
- 禁止：主线程不能清空程序员结果、项目启动记录或测试结果。
- 禁止：主线程不能清空浏览器测试窗口记录。
- 载荷：除浏览器测试窗口记录以外的固化文件路径。
- 派回：交给计划编排子代理读取旧内容。
- 归属：主线程先读取临时需求文件并处理一级标题状态。
- 完成口径：`-编写中` 或无状态标题不进入本轮处理。
- 完成口径：只有显式 `-待确认` 标题由主线程和用户实时确认或头脑风暴。
- 回写：主线程覆盖回写确认后的需求正文前，必须提取原需求正文和本次确认对话中的图片引用；覆盖后的确认正文必须继续体现这些图片引用。
- 完成口径：主线程完成需求回写且图片引用仍在正文中体现后，才把标题改为 `-已确认`。
- 完成口径：计划编排子代理只读取 `-已确认` 且未 `-完成` 的标题，并覆盖生成新的本轮计划和新的本轮测试计划。
- 禁止：计划编排子代理不得修改临时需求文件。

### 当前轮状态来源

- 归属：上一轮协作文件只作为固化记忆。
- 禁止：上一轮协作文件不能直接作为当前轮执行状态。
- 禁止：上一轮计划显示可进入测试也不能跳过计划编排闸门。
- 禁止：上一轮启动记录或测试结果显示可进入测试也不能跳过计划编排闸门。
- 归属：主线程读取当前临时需求文件并确认需求状态。
- 归属：计划编排子代理读取当前已确认且未完成需求和上一轮固化文件。
- 完成口径：所有进入本轮的需求标题都是 `-已确认` 且未 `-完成`。
- 完成口径：生成新的本轮计划和新的本轮测试计划。
- 执行：闸门完成后，再继续程序员和测试流程。

### 问题回流边界

- 触发：用户指出的问题。
- 触发：流程缺陷或子代理遗漏。
- 触发：计划或测试计划未完成。
- 触发：测试未收尾、完成标记缺失或临时图片清理缺失。
- 载荷：相关文件路径、问题描述、写入授权和期望状态要求。
- 派回：对应子代理。
- 禁止：主线程不得读取协作文件正文接管修复。
- 禁止：主线程不得代写计划、测试计划、完成标记或图片清理结果。

### 测试收尾硬闸门

- 触发：测试子代理完成全部必测项通过。
- 读取：重新读取完整本轮测试计划。
- 完成口径：必测项清单为 `[x]`。
- 完成口径：详情状态为 `通过`。
- 写入：在授权下追加临时需求一级标题 `-完成`。
- 处理：重新读取临时需求文件对应标题正文，扫描并删除本轮临时图片引用。
- 处理：正文中引用的本轮临时输入图片，删除前不再询问用户。
- 写入：把清理结果写入测试结果。
- 禁止：未完成这些收尾时，测试子代理不得返回 `状态：完成`。

临时截图、一次性交接文件等明确临时资源不属于上述协作文件。它们只能按对应模板中的授权规则清理。
