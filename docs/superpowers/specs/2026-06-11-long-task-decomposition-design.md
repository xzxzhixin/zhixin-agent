# 智能体长任务拆解设计

## 目标

把智能体长任务从“每轮默认任务状态”升级为可拆解、可续跑、可重规划、按智能体隔离展示的任务步骤体系。长任务拆解只在确实存在多个执行步骤时展示，单个默认任务不作为用户可见拆解任务。

## 产品口径

- 长任务拆解属于同一轮次同一 `taskId` 下的连续步骤，不允许把自动续跑、工具批次切换或用户补充需求拆成多个互不关联任务块。
- 主对话任务入口展示当前主对话、当前轮次、主智能体 `agentId = main` 的拆解步骤视图。
- 智能体弹框任务入口展示当前弹框对应 `agentId` 的拆解步骤视图。
- 如果当前轮次只有一个默认任务且没有拆解步骤，任务入口不展示可展开任务数量。
- 右侧任务状态栏只展示当前对话运行概览，不重复展示完整拆解列表。
- 对话消息流继续展示思考、工具调用、命令输出、MCP、skill、子智能体协作和失败详情；任务行不重复展示这些过程细节。

## 单行展示规则

拆解任务行只使用单行紧凑结构：

```text
[状态] 步骤标题                         序号/总数 · 可选耗时
```

示例：

```text
进行中  检索项目上下文                  1/5 · 00:18
待执行  生成实现计划                    2/5
已完成  更新需求与设计文档              3/5 · 00:42
失败    Chrome 验收                     4/5
替换    旧前端展示方案                  5/5
```

约束：

- 状态只在左侧显示一次，右侧不重复显示状态。
- 第二行摘要、当前动作、责任智能体、失败原因和替换原因不在任务行展示。
- 失败原因、替换原因、工具输出和当前动作由对话过程卡片或点击详情承载。
- 主对话里不重复显示“致心”，智能体弹框里不重复显示当前智能体名称。

## 数据与事件

`task_steps` 继续作为步骤事实表，并补齐长任务拆解字段：

- `plan_version`：步骤所属计划版本，默认 `1`。
- `step_order`：同一任务下的步骤顺序，从 `1` 开始。
- `source`：步骤来源，包含图节点、模型计划、todoList 工具、用户引导或系统续跑。
- `depends_on`：依赖步骤 ID JSON 数组。
- `acceptance`：该步骤完成验收口径。
- `superseded_by`：替换该步骤的新步骤 ID。
- `superseded_reason`：被替换原因。

事件口径：

- `task.step.started`：步骤开始。
- `task.step.updated`：步骤状态变化。
- `task.plan.revised`：用户中途补充或修改需求后生成新计划版本。
- `agent.loop.batch_limit_reached`：单批工具循环触顶后在同一任务内自动续跑。
- `task.updated`：任务主状态变化。

## 执行链路

- `builtin.todo.list` 必须具备明确执行器，允许模型为当前智能体写入或更新自己的拆解步骤。
- todoList 按 `sessionId + agentId` 隔离读取和展示。
- 主智能体、长期智能体和子智能体都可以维护自己的 todoList；子智能体不能继续创建下级智能体。
- 用户运行中补充需求必须走 `session.guidance.submit`，写入 `task.plan.revised`，并把不再有效的未终态步骤标记为 `superseded`。
- 自动续跑只能追加或更新同一 `taskId` 下的步骤，不能新建新任务替代当前任务。

## 验收口径

- 只有拆解步骤数量大于 `1` 时，底部任务入口显示任务数量和可展开任务面板。
- 任务面板每个步骤只显示单行：左侧状态、标题，右侧序号/总数和可选耗时。
- 右侧任务状态栏继续能看到当前对话失败、工作中、等待用户等概览。
- 运行中追加消息不会新建普通轮次，而是合并进当前任务并记录重规划事件。
- 多端通过 WebSocket 收到任务步骤、重规划和任务状态变化。
