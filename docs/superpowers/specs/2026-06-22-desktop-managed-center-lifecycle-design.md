# 桌面端托管中心服务生命周期设计

## 目标

- 确保开发版和发布版中，桌面端作为中心服务管理者退出或被强制结束后，中心服务都会自动退出。
- 保留隐藏到托盘时中心服务继续运行的现有行为，因为此时桌面壳进程仍然存活。
- 避免 IDEA 直接关闭启动进程、任务管理器强杀 Electron 或桌面壳崩溃后，中心服务继续占用端口和中心目录锁。

## 范围

- 覆盖桌面壳启动中心服务时传递生命周期管理者信息。
- 覆盖中心服务在桌面托管模式下监测管理者进程是否存活。
- 覆盖中心服务发现管理者进程消失后的优雅退出。
- 不改变 Web 端、IDE 插件端的中心服务生命周期权限。
- 不改变隐藏到托盘行为。

## 设计要点

- 桌面壳启动中心服务时新增环境变量：
  - `ZHIXIN_CENTER_LIFECYCLE_MODE=desktop-managed`：声明当前中心服务由桌面端托管。
  - `ZHIXIN_CENTER_MANAGER_PID`：桌面壳主进程 PID。
  - `ZHIXIN_CENTER_MANAGER_CHECK_INTERVAL_MS`：可选检查间隔，缺失时中心服务使用默认间隔。
- 桌面壳健康检查通过后必须调用中心服务本机生命周期登记接口，把当前桌面壳 PID 写入正在运行的中心服务；该接口用于覆盖复用遗留中心服务的场景。
- 中心服务只在 `ZHIXIN_CENTER_LIFECYCLE_MODE` 为 `desktop-managed` 且 `ZHIXIN_CENTER_MANAGER_PID` 是合法正整数时启用管理者监护。
- 管理者监护使用跨平台进程判活逻辑定时检查桌面壳 PID。
- 当管理者 PID 不再存活时，中心服务写入“桌面端管理者进程消失”日志，调用现有 `service.close()`，释放 HTTP 服务、SQLite、临时目录和 `.zhixin-center.lock`，随后以 `0` 退出。
- 正常退出仍走 Electron `before-quit -> stopManagedCenterService`，开发脚本正常停止仍走 `dev-desktop-shell.mjs` 的锁文件兜底清理。
- IDEA 强制停止、任务管理器强杀 Electron、桌面壳崩溃等没有 JS 退出钩子的路径，由中心服务管理者监护兜底。

## 错误处理

- 管理者 PID 缺失、非法或生命周期模式不是 `desktop-managed` 时，不启用监护，避免独立中心服务或测试脚本被误关。
- 桌面管理者登记接口只允许本机请求，Web 端和 IDE 插件端不能通过远程请求接管中心服务生命周期。
- 进程判活出现 `EPERM` 时视为进程仍存在，避免权限导致误判。
- 中心服务正在关闭时，管理者监护不得重复触发关闭。
- `service.close()` 失败时记录错误并设置非零退出码，避免静默残留。

## 验收口径

- 正常退出桌面端后，中心服务停止，`8866` 端口释放。
- 开发环境中强杀 Electron 主进程后，中心服务在检查间隔后主动退出，`8866` 端口释放。
- 发布版桌面壳被强杀后，中心服务在检查间隔后主动退出。
- 第二次启动复用上一轮遗留中心服务后，当前桌面壳 PID 会登记到既有中心服务，当前桌面壳被强杀后既有中心服务也会自动退出。
- 隐藏到托盘后，桌面壳进程仍存在，中心服务继续运行。
- 不带 `desktop-managed` 生命周期模式直接启动中心服务时，不启用管理者监护。
- 中心服务管理者监护路径有文件日志记录，便于排查异常退出。

## 清单状态

- ⏳ 桌面壳生命周期环境变量
- ⏳ 中心服务管理者监护
- ⏳ 管理者消失后优雅退出
- ⏳ 强杀场景回归
- ⏳ 文档事实源同步
