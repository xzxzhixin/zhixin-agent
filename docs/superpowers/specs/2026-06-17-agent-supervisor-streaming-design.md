# Agent 任务监督与实时过程渲染设计

## 目标

- ⏳ 把 Deep Agents 单次 graph 停止和致心任务完成标准拆开，避免模型只返回过程文本或非法工具形态时被中心服务误判为完成。
- ⏳ 让中心服务在同一轮次、同一任务下接管续跑、重试、等待用户和失败收尾，Deep Agents 只负责一次模型-工具循环。
- ⏳ 让模型中途文本、工具请求、工具执行和工具结果事件在运行中实时进入前端消息流，不等最终助手消息或轮次终态才展示。

## 范围

- ⏳ 覆盖 `services/center/src/deepagents-agent.ts` 的 Deep Agents 执行收尾、候选终态判断、续跑预算和失败/等待用户收尾。
- ⏳ 覆盖前端对 `event.appended` 的实时事件合并、过程卡片行生成和快照覆盖保护。
- ⏳ 覆盖回归检查脚本、浏览器真实操作验收和 IDEA Run Configuration 启动验收。
- ⏳ 不覆盖供应商协议重写、不覆盖从普通文本恢复工具调用、不覆盖按具体 MCP 工具名或用户提示词硬编码调度。

## 设计要点

### Deep Agents 停止标准

- ⏳ Deep Agents 自身的停止标准仍按 LangGraph/ReAct 语义运行：模型返回结构化 `tool_calls` 时继续工具循环，模型没有返回结构化 `tool_calls` 时本次 graph 结束。
- ⏳ 中心服务不得把本次 graph 结束直接视为任务完成，只能视为一次运行候选结果。
- ⏳ 运行候选结果包含最终助手文本、流式文本、模型工具诊断、工具事件摘要、任务状态摘要、尝试次数和异常摘要。

### 中心服务任务完成网关

- ⏳ 新增 `AgentCompletionGate`，只判断“本次 Deep Agents 候选结果是否可以固化为最终助手回复”。
- ⏳ 候选结果满足以下条件之一时不能直接完成：模型最后一次没有结构化工具调用且文本仍是过程态；模型把 `name`、`args` 或类似工具调用字段放在普通 `content.type = text` 内容中；本轮刚产生工具结果但模型没有基于结果形成总结；当前任务或可见步骤仍处于 running/pending；工具持续失败但仍存在替代路径预算。
- ⏳ 完成网关不读取用户提示词、不硬编码工具名、不从文本恢复工具调用，只输出 `completed`、`continue`、`retry`、`waiting_user` 或 `failed`。
- ⏳ 新增 `DeepAgentTurnSupervisor`，负责在同一 `turnId` 和 `taskId` 下多次调用 Deep Agents，直到完成网关返回终态或预算耗尽。
- ⏳ Supervisor 续跑时向 Deep Agents 追加内部系统提示，提示模型继续完成任务或使用结构化工具调用；该提示只进入模型上下文，不固化为用户可见消息。
- ⏳ 预算包含最大总尝试次数、协议形态重试次数、无进展重试次数和工具失败重试次数；预算耗尽后才进入等待用户或失败终态。

### 过程文本与非法工具形态

- ⏳ 模型中途返回“我正在读取”“下一步筛选”等过程文本是正常事件，应作为 `model.stream.delta` 进入无标题 Markdown 过程卡片。
- ⏳ 过程文本不能创建 `message.created` 助手最终消息，不能触发记忆写入，也不能完成任务。
- ⏳ 模型把工具字段放入普通文本时，中心服务记录协议诊断事件并重试，提示模型必须使用结构化 `tool_calls`；中心服务不把文本字段转换成真实工具调用。
- ⏳ 连续多次只返回过程文本、连续非法工具形态、工具持续失败且没有替代路径、超过监督预算，才收敛为等待用户或失败。

### 实时事件渲染

- ⏳ 后端每次追加过程事件后必须通过既有 `event.appended` 实时推送给当前会话订阅客户端。
- ⏳ 前端收到当前会话 `event.appended` 后必须立即用新数组引用合并到 `appStore.events`，过程卡片和中途 Markdown 行基于该数组即时重算。
- ⏳ 完整快照只能补齐事实，不能覆盖掉已经通过 WebSocket 收到且序号更新的运行中过程事件。
- ⏳ `message.created`、`model.stream.completed`、`turn.updated`、`turn.state.changed` 和 `task.updated` 可触发快照兜底，但不能成为过程卡片出现的唯一来源。
- ⏳ 浏览器验收必须用真实输入触发一次带模型流式文本和工具事件的任务，观察卡片在运行中出现，再等待最终回复和终态收敛。

## 验收口径

- ⏳ 模型先合法调用工具、工具回填后又返回普通 text 伪工具调用字段时，本轮不会立即创建最终助手消息，Supervisor 会续跑或重试。
- ⏳ 模型连续返回过程文本且没有结构化工具调用时，本轮不会被标记完成，预算内继续，预算耗尽后给出可展示失败或等待用户终态。
- ⏳ 模型已经给出满足用户目标的最终总结时，中心服务只创建一次助手消息、写一次记忆、完成一次任务和轮次。
- ⏳ 真实工具请求、工具执行、工具结果回填、中途模型 Markdown 都在运行中通过 `event.appended` 出现在前端消息流。
- ⏳ 一轮完成后，过程卡片保留终态，发送按钮恢复“发送”，当前轮次耗时不残留运行态。
- ⏳ 回归检查脚本覆盖监督层续跑、预算耗尽、最终完成和前端事件即时合并。
- ⏳ 使用 IDEA Run Configuration `dev:desktop-shell` 启动，并通过 Chrome DevTools 浏览器真实点击、输入和观察完成验收。
